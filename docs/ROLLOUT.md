## Phase 1 · 把代码改动安全部署到模拟盘

**适用**:TODO 里的 T2–T8(纯代码改动,不涉及真钱)。

**发布流程(每次改动一遍)**
1. 本地改 → `python -m py_compile` 语法过 → `git diff` 自查
2. 若改了交易逻辑:先本地/回测验证,再 commit
3. `git push` → 服务器 `git pull --ff-only`
4. **在安全窗口重启**:美东 **收盘后 ~11:00 ET 之后、次日 9:15 ET 之前**(无持仓、无 session),`systemctl restart cameron-autotrader`
5. 验证:`journalctl -u cameron-autotrader -n 20` 确认新进程、无报错、在等开盘

**安全门槛**
- ✅ 单实例锁保证不会双开
- ✅ 改动只碰一个模块;日志类改动(如 T0)可随时上
- ⚠️ 交易逻辑改动(T2/T6/T8)**先回测**再上
- 🔙 回滚:`git revert` + 重启,或服务器 `git reset --hard <上一个commit>` + 重启

**Phase 1 完成标准**:P2/P3 里选定的改动上线且稳定运行 ≥1 周无异常。

## Phase 2 · 影子 → 实盘 的策略晋升

**适用**:T1(把 `orb5-dip` 或任何影子转正)。

**晋升门槛(全部满足才换)**
1. 该影子累计 **≥30 笔**成交(足够样本)
2. **总 R 明显跑赢**现任实盘(不是一两天的运气;看整段 `variants.csv`)
3. 正期望且**最大回撤**在可接受范围
4. 回测与影子结论**方向一致**(避免过拟合)

**换马操作**
1. 在 `autotrader.py` 把目标策略移入实盘配置、把现任降为影子(改 `SHADOW_VARIANTS` / live 分支)
2. **保留旧策略作影子**继续对照(像现在的 `orb5-plain`)
3. 走 Phase 1 发布流程上线
4. 上线后**盯 5 个交易日**:真实成交价 vs 影子预期是否吻合(警惕执行差,如 WLDS 的 $0.04)

**Phase 2 完成标准**:新实盘策略连续 2 周表现符合影子预期,无执行偏差。

## Phase 3 · 模拟盘 → 真钱(最谨慎)

> ⚠️ 只有 Phase 1/2 都稳、且下列门槛**全部**达标才考虑。宁可多等。

**准入门槛**
1. 实盘策略(模拟盘)累计 **≥50–100 笔**、跨 **≥2–3 个月**、不同市场环境
2. **正期望**稳定:总 R > 0 且非单笔/单日贡献主导
3. **最大回撤** < 预设上限(如账户的 10–15%)
4. 执行零系统性偏差(滑点/漏单可控)
5. 全流程自动化稳定运行 ≥1 个月无人工干预事故

**真钱上线设计**
- **小资金起步**:用能承受全损的金额(如目标资金的 10–20%)
- **同比例缩小风险**:`RISK_PER_TRADE`、`DAILY_MAX_LOSS` 按真实资金重设,先设更保守
- **并行观察期**:真钱与模拟盘同跑一段,对比成交质量
- **每日复核 + 硬熔断**:保留 −X% 日止损、总回撤熔断
- **合规/税务**:确认账户类型、PDT 规则(<$25k 的日内交易限制)、税务申报

**Phase 3 完成标准**:小资金真钱运行达标后,再逐步增资。**没到就一直留在模拟盘。**
